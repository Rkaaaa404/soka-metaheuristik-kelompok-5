02 / Landasan konseptual

Ruang pencarian besar.
Strategi harus lebih cerdas.

Mengapa Cloud Task Scheduling membutuhkan keseimbangan exploration dan exploitation?

01 / Tantangan

Penjadwalan adalah masalah NP-Hard.

Pada infrastruktur cloud modern, ribuan task independen (workload batch) dengan panjang instruksi (MI) dan waktu kedatangan (arrival time) berbeda harus dialokasikan ke puluhan virtual machine (VM) heterogen.

Untuk N task dan M VM, terdapat MN kemungkinan pemetaan. Pada N = 1000 dan M = 10, ruang pencarian mencapai 101000. Pencarian eksak (exhaustive search atau ILP) menjadi tidak praktis untuk skenario ini secara real-time.

02 / Pendekatan

Jelajahi kemungkinan. Pertajam solusi.

Metaheuristik adalah kerangka optimasi tingkat tinggi yang menyeimbangkan dua mekanisme utama:

  • Exploration (Diversifikasi): Menjelajahi ruang solusi yang belum terjamah untuk keluar dari jebakan optimum lokal (local optima).
  • Exploitation (Intensifikasi): Memanfaatkan informasi di sekitar kandidat solusi terbaik untuk menyempurnakan hasil.

Meskipun tidak memberikan jaminan matematis menemukan solusi global optimum, metaheuristik secara empiris menghasilkan jadwal mendekati optimum dengan makespan dan efisiensi energi yang jauh lebih baik dalam hitungan detik.

03 / Teori & mekanisme

Dua inspirasi. Dua cara beradaptasi.

Konsep & Alur Clonal Selection Algorithm

CSA terinspirasi oleh teori seleksi klonal pada sistem imun adaptif tubuh manusia. Antibodi (kandidat jadwal) bersaing mengikat antigen (tujuan optimasi).

  1. Inisialisasi Populasi: Bangkitkan P antibodi acak. Setiap gen mewakili penugasan VM untuk task tertentu.
  2. Evaluasi Afinitas: Hitung fitness skalar F = w · (T / Tref) + (1 − w) · (E / Eref), dengan T makespan dan E konsumsi energi host. Afinitas didefinisikan sebagai 1 / (1 + F).
  3. Seleksi & Kloning: Pilih K antibodi dengan afinitas tertinggi. Parent rank r menghasilkan klon proporsional: Cr = ⌊β · P / r⌋.
  4. Hipermutasi Terbalik (Affinity-Dependent Hypermutation): Klon dari parent berafinitas tinggi mengalami laju mutasi rendah, sedangkan klon rank rendah bermutasi agresif (pr).
  5. Arsip Pareto (Non-Dominated Front): Solusi trade-off (T, E) yang tidak saling mendominasi disimpan sepanjang generasi.

Konsep & Alur Polyrhythmic Harmony Search

PHS dikembangkan oleh Melnik & Trofimenko (2015) berdasarkan metafora improvisasi harmoni musik jazz dengan ritme heterogen. Ciri khas PHS yang membedakannya dari Harmony Search generik adalah Dual Harmony Memory (Memory Jadwal dan Memory Sumber Daya).

  1. Dual Harmony Memory: Schedule HM menyimpan urutan eksekusi dan penugasan VM; Resource HM menyimpan faktor kapasitas per VM (0, 0.5, 1.0).
  2. Inisialisasi Seed HEFT: Entry 0 kedua memory dibentuk dari HEFT (Heterogeneous Earliest Finish Time) dengan kapasitas penuh untuk menjamin start yang kuat.
  3. Alternasi Ritme Poliritmik: Iterasi genap mengimprovisasi jadwal (reassign VM / swap urutan); iterasi ganjil mengimprovisasi alokasi resource (deactivate / activate / reduce).
  4. Crossbreed Khusus: Crossover dua-titik pada jadwal menjaga permutasi utuh; crossover resource melakukan interleaving VM aktif di bawah batasan kapasitas total.
  5. Mekanisme Reparasi: Penugasan ke VM non-aktif secara otomatis dipindahkan ke VM aktif tercepat sebelum evaluasi makespan.
